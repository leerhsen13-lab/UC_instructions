## Привет! Я Дарья — технический писатель
Специализируюсь на создании понятной документации для сложных продуктов. Умею переводить с «разработческого» на человеческий и выстраивать процессы «Docs as Code».

### Мой стек инструментов:
*   **Разметка:** Базовый Markdown (структурирование, таблицы, ссылки).
*   **Редакторы:** VS Code (настроен под работу с документацией).
*   **Контроль версий:** Git & GitHub — активно осваиваю на практике (публикация правок, управление репозиториями).
*   **Визуализация:** Создание схем через Mermaid.js, работа со скриншотами.

### Что в этом репозитории?
Здесь собраны примеры моих работ, которые демонстрируют разные подходы к документации:

1.  **[Процесс управления запросами (ITIL)](https://github.com/leerhsen13-lab/UC_instructions/blob/e745a54bbfb9aab0ddab1e926e8e54a8936c3efb/%D0%9F%D1%80%D0%BE%D1%86%D0%B5%D1%81%D1%81%20%D1%83%D0%BF%D1%80%D0%B0%D0%B2%D0%BB%D0%B5%D0%BD%D0%B8%D1%8F%20%D0%B7%D0%B0%D0%BF%D1%80%D0%BE%D1%81%D0%B0%D0%BC%D0%B8%20(ITIL).md)**
    *   **Для кого:** Руководители ИТ-отделов, специалисты службы поддержки (Service Desk), сотрудники ИТ-департамента.
    *   **О чем:** Регламент взаимодействия между пользователем и ИТ-службой в рамках методологии ITIL. Документ описывает жизненный цикл запроса: от классификации и оценки приоритета до контроля качества выполнения (SLA) и закрытия заявки..

2.  **[Памятка по работе в ITSM-системе (Quick Start Guide)](https://github.com/leerhsen13-lab/UC_instructions/blob/e745a54bbfb9aab0ddab1e926e8e54a8936c3efb/%D0%9F%D0%B0%D0%BC%D1%8F%D1%82%D0%BA%D0%B0%20%D0%BF%D0%BE%20%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%B5%20%D1%81%20%D0%B7%D0%B0%D0%BF%D1%80%D0%BE%D1%81%D0%B0%D0%BC%D0%B8%20%D0%B2%20HPSM.md)**
    *   **Для кого:** Все сотрудники ИТ-департамента, включая новых специалистов и смежные команды.
    *   **О чем:** Прикладной справочник по выполнению ежедневных операций в ITSM-системе. Документ переводит формальный процесс управления запросами на язык практических действий.
    *   **Формат:** Выполнено в стиле FAQ (Вопрос — Ответ) для максимально быстрого поиска решения конкретной задачи.
    *   **Фишка:** Памятка построена по принципу «проблема — решение», снабжена наглядными скриншотами-подсказками и исключает избыточную теорию в пользу скорости работы.

4.  **Инструкции по администрированию прав доступа: [Oracle data bases](https://github.com/leerhsen13-lab/UC_instructions/blob/e745a54bbfb9aab0ddab1e926e8e54a8936c3efb/OracleDB.md) и [CRM Siebel](https://github.com/leerhsen13-lab/UC_instructions/blob/e745a54bbfb9aab0ddab1e926e8e54a8936c3efb/CRM%20Siebel.md)**
    *   **Для кого:** Администраторы ИТ систем.
    *   **О чем:** Полный цикл управления учетными записями в БД Oracle и CRM Siebel. Включает процедуры аутентификации, создания профилей и настройки ролевой модели. Документ структурирован по принципу Step-by-Step для минимизации ошибок при настройке прав.
    *   **Фишка:** Описаны критические сценарии (отзыв прав при увольнении, аудиторские проверки, типовые решения инцидентов)
