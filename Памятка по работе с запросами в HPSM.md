# Памятка по работе с запросами в HPSM

## Описание запроса, задачи и для чего они нужны.
**Запрос** – обращение пользователя по ИТ-услуге. Включает в себя запросы на выполнение действий и запросы информации и консультации. Запрос может быть сформирован из
обращения(HD), инцидента(INC) и изменения(CHG), а так же существовать отдельно (регламентные работы).

**Задача** - задание на выполнение работ по запросу.

Задачи в запросе необходимы, так как:
- может быть несколько задач на разных исполнителей;
- задачу можно приостановить;
- может потребоваться внимание координатора запроса.

> Для изменения шаблонов запросов и/или задач оформите Изменение по шаблону: HPSM
Запросы: Создание / Изменение / Удаление шаблона (IT4U Portal, HPSM)

> Правила реагирования в случае, если заявитель обратился напрямую к специалисту в
обход Службы SD:
- специалист напоминает заявителю правила, согласно которым все обращения должны регистрироваться через Службу SD;
- просит создать запрос через IT4U Portal / IAM One Identity / Заявки ДИТ или обратиться в Службу SD (телефон или почта).

## Описание ролей участников процесса
### 
Область ответственности: корректность подачи запросов в Службу SD.

Перечень функций:
- предоставляет дополнительную информацию по запросу в Службу SD;
- принимает участие в закрытии запроса.

### 
Область ответственности:
- согласование запроса в установленные сроки;
- оперативный контроль согласования запроса в установленные сроки (для координатора группы согласования).

Перечень функций:
- согласование запросов;
- координация согласований запросов, назначенных на его группу согласования (для координатора группы согласования).

### 
Область ответственности: оперативный контроль обработки и выполнения задач в рамках запроса.

Перечень функций:
- координация запросов, требующих внимания;
- координация запросов с нарушением последовательности работ;
- контроль выполнения задач в рамках запроса.

###
Область ответственности:
- сроки и качество выполнения запросов / задач по запросу;
- своевременное распределение запросов / задач по запросу, назначенных в рабочую группу;
- своевременный контроль исполнения задач по запросу, назначенных на рабочую группу: до истечения крайнего срока задача по запросу, должна быть выполнена исполнителем рабочей группы.

Перечень функций:
- распределение запросов / задач по запросу на исполнителей рабочей группы;
- контроль сроков выполнения запросов / задач по запросу, назначенных на рабочую группу;
- актуализация состава рабочих групп.

###
Область ответственности:
- соблюдение сроков и обеспечение качества выполнения работ по запросам / задачам по запросам;
- своевременное выполнение задач по запросу, с момента принятия в работу до истечения крайнего срока задачи по запросу,

Перечень функций:
- выполнение запросов / задач по запросу;
- оформление и протоколирование предпринятых действий в рамках выполнения запросов / задач по запросу;
- своевременное обновление в ITSM-системе статуса запроса / задачи по запросу;
- своевременный контроль за корректностью назначения запросов / задач по запросу на рабочую группу;
- выполняет необходимые оповещения пользователей в ходе выполнения запросов.

## Работа с запросами REQ
?
В системе доступны следующие коды закрытия запроса:
- Решен - если запрос выполнен;
- Прекращен - отсутствует техническая возможность в выполнении данного запроса в настоящее время, поле «Решение для пользователя» обязательно к заполнению;
- Отклонен - нарушает внутренние регламенты, неверный выбор шаблона запроса, поле «Решение для пользователя» обязательно к заполнению;
- Не согласован - запрос не согласован.

?
- Нажмите "Создать задачу";
- Введите название рабочей группы исполнителя и нажмите "Активировать".

## Ответы на вопросы
Q: *Как правильно оформлять запросы на группу сотрудников?*

*Например ранее в CM была Заявка на доступ к информационным системам с вложенным Excel. В Excel возможно было прописать права для 20+ сотрудников отдела и далее Заявка загружалась в HPSM. Теперь, после перевода Заявки в HPSM получаем отказы принимать заявку с вложенным Excel на нескольких сотрудников, с требованием оформить индивидуальные. Но 20+ раз оформлять и согласовывать однотипные заявки тоже не хотелось бы, это доп. нагрузка и на нас, и на линии поддержки, которые их будут обрабатывать*
A: Необходимость индивидуального обращения на каждого пользователя обусловлена тем, что все обращения сохраняются в истории на IT4U Portal, и могут быть использованы в дальнейшем для решения проблем или повторных обращений.

Q: *Как расчитывается крайний срок выполнения запроса? Почему на какие-то запросы дается две недели, а на какие-то месяц?*
A: Крайний срок запроса и задачи определяется шаблоном, учитывая технические особенности исполнения.

Q: *Также отдельно еще хочется спросить про задачи по запросам – для чего их создают? Когда в работу приходит запрос то, при необходимости, его можно переназначить на другую группу, с дополнительными комментариями/вопросами и т.д. Когда же приходит задача по запросу – работать с ней неудобно, если требуется ее кому-то перенаправить, то приходится делать возврат, писать кому ее надо переназначить, после этого (полагаю Help Desk), когда до нее дойдет очередь ее рассмотрит и только тогда перенаправит на другую группу – теряется оперативность работы.*
A: Задача - задание на выполнение работ по запросу; запрос - обращение пользователя по ИТ-услуге./
Исполнитель запроса также выступает в роли координатора запроса, который контролирует получение пользователем запрошенной услуги в полном объеме. При отрицательном коде закрытия или возврате задачи координатор запроса анализирует ситуацию и принимает меры (например: создает дополнительные задачи, меняет исполнителя и т.д.). При необходимости можно создать шаблон обращения, в котором в качестве координатора запроса будет указана рабочая группа исполнителя (вместо группы координаторов). В таком случае ответственность за получение пользователем услуги в полном объеме будет нести установленная рабочая группа. Область ответственности и перечень функций у исполнителя задачи отличается от координатора запроса. См. "Описание ролей участников процесса".

Q: *Когда полностью откажемся от СМ в пользу HP SM?*
A: Активно ведутся работы по переносу шаблонов из CMA БД Заявки ДИТ. Остались шаблоны, с которыми возникли трудности и для переноса требуются бóльшие трудозатраты.
На данный момент уже перенесено:
- На *Portal1* ~100 шаблонов;
- На *Portal2* ~70 шаблонов.

Q: *Кто несет ответственность за несоблюдение SLA по задачам, и почему часто происходит это несоблюдение?*
A: Ответственность за соблюдением сроков и качества выполненных работ несет исполнитель и координатор рабочей группы. См. "Описание ролей участников процесса"./
При необходимости координатор РГ совместно с исполнителями могут рассмотреть возможность изменения срока исполнения задач, как в большую, так и в меньшую сторону. См. "Изменение шаблона"
